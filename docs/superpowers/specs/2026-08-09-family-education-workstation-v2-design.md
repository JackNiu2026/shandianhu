# 闪电虎 V2 家庭教育工作站设计规格

## 1. 文档定位

本文档定义闪电虎 V2 的产品总蓝图与技术边界。V2 将产品从“AI 家教撮合”升级为“AI 家教 + 真人家教融合的一站式家庭教育工作站”。

本文档是三个可独立发布里程碑的上层设计，不作为一份不可拆分的单体实施计划。后续实施计划必须按 V2.1、V2.2、V2.3 分别编写、执行和验收。

## 2. 产品目标

目标用户为 K12 家长。家长通过微信小程序管理一个或多个孩子，并围绕同一份持续更新的学习画像使用三类服务：

1. 学情分析评估：提交错题图片、完成学习风格测评并获得详细报告。
2. AI 家教：使用按学科和学段配置的智能体进行文字与图片辅导。
3. 真人家教：根据孩子画像匹配老师，完成试听、课程和反馈闭环。

三个系统必须共享孩子学习档案，形成以下闭环：

`学情评估 -> 学习画像 -> AI 家教 / 真人家教 -> 学习记录与反馈 -> 更新学习画像`

## 3. 已确认的产品决策

- 本次只交付微信小程序，不开发原生 App 或正式 H5 版本。
- 首次使用采用渐进式建档，不强制完成全部评估后才能使用其他功能。
- 一个家长账号可以管理多个孩子。
- 当前孩子只能在“我的”页面切换，其他业务页面自动使用当前孩子。
- 家长端底部导航为“智学、家教、学情、我的”。
- 首次建档后自动进入“学情”；完成或跳过后，日常启动默认进入“智学”。
- 评估底层采用模块化架构，V2 首期只实现错题诊断和学习风格测评。
- 错题诊断只生成批次评估报告，不建立错题本。错题本属于后续老师端版本。
- 综合报告采用结构化分析与大模型叙述结合的方式。
- 报告同时提供小程序内交互视图和脱敏 PDF。
- AI 家教由孩子在家长账号下直接使用，不建立孩子独立登录账号。
- AI 家教首期覆盖语文、数学、英语、物理和化学。
- 具体教学策略由管理员上传的智能体系统提示词控制，不硬编码在业务逻辑中。
- 模型接入采用 OpenAI-compatible 通用网关，并支持主模型和备用模型。
- AI 家教采用文字分块流式输出并支持图片输入。
- 本次不实现任何语音功能；豆包、千问全双工语音进入后续版本。
- AI 使用采用免费体验额度和后台人工调整，本次不接在线购买。
- AI、学情与真人家教采用双向数据融合。
- 老师与家长共用同一小程序代码库，但使用真实、独立的角色权限。
- 老师自主申请并由平台审核，通过后才能上线。
- 真人家教完成试听、排期、课程和反馈闭环，本次不接在线支付。
- 后台本次仍只有超级管理员，不开发 RBAC。
- 用户认证采用微信一键登录，不以手机号密码作为首次进入门槛。
- 本次只实现站内通知，不接微信订阅消息。
- 文件使用腾讯云 COS；生产 PostgreSQL 使用用户已有的腾讯云数据库。
- 异步任务使用 Redis 队列。
- 首轮按 20 至 200 个家庭的小范围 Beta 设计。
- 现有数据库没有需要保留的真实生产数据，可以建立全新基线迁移。

## 4. 交付里程碑

### 4.1 V2.1 学情底座

- 微信一键登录。
- 家长资料与多孩子档案。
- 当前孩子全局上下文。
- 错题批次诊断。
- 学习风格测评。
- 学习证据与版本化学习画像。
- 小程序内综合报告。
- PDF 生成、下载和限时分享。
- COS、Redis、Worker 和站内通知基础能力。
- OpenAI-compatible 模型网关基础、评估模型配置和全局模型用量日志。

### 4.2 V2.2 智学系统

- 五科学科智能体工作台。

- 多会话历史与结构化辅导摘要。

- 家庭级 AI 家教额度、额度流水和模型成本关联。

### 4.3 V2.3 真人闭环

- 老师身份申请与资质审核。

每个里程碑必须独立完成数据库迁移、自动测试、部署、验收和回滚验证。

## 5. 总体架构

项目继续采用 pnpm monorepo 和模块化单体架构。

### 5.1 包职责

- `packages/mobile`：Taro 4 微信小程序，负责界面、交互和短期客户端状态。
- `packages/admin`：Next.js 管理后台，同时作为 HTTP、API 和流式响应适配层。
- `packages/server`：新增服务端核心包，拥有 Prisma、领域服务、权限规则、模型网关、COS 和队列定义。
- `packages/worker`：新增异步 Worker，消费 Redis 评估、画像、报告和 PDF 任务。
- `packages/shared`：只保存跨端 API 契约、枚举和无副作用纯函数。

生产演示老师数据不得继续作为运行时降级数据存放在 `shared` 中。

### 5.2 服务边界

Next.js Route Handler 只负责：

1. 认证与授权入口。
2. 请求 Schema 解析。
3. 调用 `server` 中的领域服务。
4. 将领域结果转换为 HTTP 或流式响应。

Route Handler 不直接拼装业务状态机，也不直接散落 Prisma 操作。后台页面、普通 API、AI 流式接口和 Worker 使用同一套领域规则。

### 5.3 生产进程

- `admin` 进程：管理后台、普通 API、微信登录回调和 AI 文字流式接口。
- `worker` 进程：Redis 队列消费者。
- Nginx：HTTPS、反向代理、静态资源缓存和入口限流。
- 外部依赖：腾讯云 PostgreSQL、Redis、COS 和模型服务。

### 5.4 同步与异步链路

同步链路用于微信登录、档案操作、列表查询、预约状态操作和 AI 实时对话。

异步链路用于错题图片分析、学习画像重算、报告叙述生成、PDF 生成和通知投递。异步 API 创建任务后立即返回 `taskId`，小程序查询任务状态，不保持长时间 HTTP 请求。

AI 实时对话不进入长任务队列。会话完成后的结构化摘要与画像更新可以异步执行。

### 5.5 平台公共实体

- `FileObject`：COS 对象元数据和所有权。
- `AsyncJob`：异步任务的数据库事实记录；Redis/BullMQ 只负责调度和投递。
- `Notification`：站内通知、已读状态和业务跳转目标。
- `AuditLog`：后台敏感操作和关键数据删除记录。

数据库中的 `AsyncJob` 是用户可见任务状态的来源。Worker 每次领取、重试、成功或失败都同步更新该记录，不能只依赖 Redis 中可能过期的队列状态。

## 6. 身份与孩子模型

### 6.1 核心实体

- `User`：微信身份、昵称、手机号、账号状态。
- `ParentProfile`：家长业务资料与当前孩子引用。
- `Child`：孩子称呼、出生年、年级、学校信息和学习目标。
- `TeacherProfile`：老师身份、审核状态、科目、学段和公开资料。
- `AuthSession`：微信小程序用户的服务端会话、到期时间和撤销状态。
- `AdminUser` 与 `AdminSession`：独立于微信用户的后台超级管理员身份与会话。

同一 `User` 可以同时拥有家长和已审核老师身份，但每次 API 调用必须在明确角色上下文中授权。后台超级管理员不复用 `User` 或小程序会话。

### 6.2 微信登录

1. 小程序调用 `wx.login` 获取临时 code。
2. 服务端通过微信接口换取 `openid`，创建或查询 `User`。
3. 服务端签发自己的登录会话。
4. 家长主路径完成家长称呼与第一个孩子的基础建档。
5. 登录页和无孩子的“我的”页保留次级“老师入驻”入口；纯老师申请者可以直接创建老师申请，不得被强制创建虚假孩子档案。
6. 手机号仅在真人家教联系等必要场景请求微信授权，不作为首次进入门槛。

### 6.3 当前孩子

- 当前孩子保存为家长资料的 `activeChildId`。
- 只有“我的”页面提供孩子新增、编辑和切换。
- “智学”“家教”“学情”只显示当前孩子，不提供切换控件。
- 无有效当前孩子时，业务入口统一引导到“我的”完成建档。
- 所有评估、会话、报告、预约、课程、额度和通知必须绑定明确的 `childId` 或家庭账号。

## 7. 学习画像模型

学习画像采用“证据 + 版本”而不是可覆盖的单份 JSON。

### 7.1 核心实体

- `LearningEvidence`：记录证据来源、来源实体、采集时间、学科和结构化内容。
- `LearningProfile`：孩子当前有效画像及当前版本引用。
- `LearningProfileVersion`：每次重算后的不可变快照、来源集合、生成规则、模型和可信度。不可变表示内容不能原地修改；隐私删除可以将版本撤销并按删除流程清理。

证据来源包括：

- 错题评估结果。
- 学习风格测评结果。
- AI 家教结构化摘要。
- 真人老师课后反馈。

### 7.2 画像内容

- 学科知识点与当前掌握证据。
- 常见错误类型和优先薄弱项。
- 理解、反馈和学习节奏偏好。
- 最近辅导与老师反馈反映的变化。
- 每项结论的数据来源、时间和可信度。

综合画像不使用一个无法解释的统一总分。可信度由证据数量、来源类型、覆盖范围和时间衰减规则计算，不使用模型自行声称的置信度。

## 8. 学情评估系统

### 8.1 模块框架

- `AssessmentDefinition`：评估模块定义。
- `AssessmentVersion`：题目、规则或分析配置版本。
- `AssessmentRun`：一次评估任务及状态。
- `AssessmentArtifact`：评估输入文件。
- `AssessmentResult`：结构化结果和家长可读叙述。

V2 只启用两个模块，不开发可视化通用题库编辑器或第三种评估。

### 8.2 错题诊断

流程：

`选择学科 -> 上传 1 至 9 张图片到 COS -> 创建评估任务 -> Worker 调用视觉模型 -> Schema 校验 -> 保存结果 -> 写入学习证据 -> 重算画像 -> 更新综合报告`

结构化结果至少包括题目识别、知识点、错误类型、逐题分析、掌握度和学习建议。

本次不实现错题收藏、错题复习、重新作答或掌握状态跟踪。任务失败时保留可重试输入，不生成随机报告，不写入虚假画像。评估调用不消耗“智学”家庭额度，成功与失败均写入全局模型用量日志。

### 8.3 学习风格测评

- 首期沿用现有 28 题四维框架。
- 题目与评分规则纳入 `AssessmentVersion`。
- 评分由确定性代码执行。
- 大模型只负责生成易读说明，不得修改类型和维度结果。
- 页面明确说明结果是教学偏好参考，不是心理诊断或能力评价。

### 8.4 综合报告

完成任意一项评估即可生成初版报告。新评估、AI 辅导摘要或老师反馈进入后生成新的画像与报告版本。

系统先保存知识点、错误类型、分数和证据等结构化事实，再由大模型生成家长易读的叙述。叙述不得修改结构化事实。

报告提供：

- 小程序内交互式概览、证据、建议和历史变化。
- Worker 异步生成的脱敏 PDF。
- 有期限、可撤销的报告分享链接。
- 模型、提示词、评估和画像版本追溯信息。

`LearningReport` 保存综合报告版本、关联的画像版本、生成状态、结构化正文、叙述版本、PDF 文件引用和分享状态。

## 9. AI 家教智能体系统

### 9.1 智能体配置

每个智能体按“学科 + 学段”配置。首期支持：

- 语文、数学、英语：小学、初中、高中。
- 物理、化学：初中、高中。

核心实体包括：

- `AgentConfig`。
- `AgentPromptVersion`。
- `ModelConfig`。

提示词后台支持文本或 Markdown 上传、在线编辑、草稿、测试、发布、历史版本和回滚。每次会话记录实际使用的提示词与模型版本。

运行时上下文顺序固定为：

`平台安全边界 -> 已发布学科提示词 -> 当前孩子画像摘要 -> 本次任务与图片 -> 必要历史摘要 -> 当前对话`

具体教学策略由管理员上传的学科提示词控制，不在业务代码中硬编码。

### 9.2 模型网关

模型网关统一支持 OpenAI-compatible 服务。配置包含服务地址、加密 API Key、模型名、文字/视觉能力、超时、最大输出、温度、成本参数和启停状态。

V2.1 先由评估和报告任务使用同一网关；V2.2 在此基础上增加学科智能体路由。每个智能体可指定主模型和备用模型。客户端不得获得模型密钥或完整系统提示词。

`ModelUsageLedger` 记录评估、报告叙述、提示词测试和 AI 家教等全部模型调用的用途、模型、Token、耗时、费用与脱敏错误元数据。它只负责平台成本核算，不等同于用户可用额度。

### 9.3 智学工作台

“智学”首页展示：

- 当前孩子的简短学习状态。
- 当前学段适用的学科智能体。
- 继续最近辅导。
- 新建辅导。
- 近期辅导摘要。

每个孩子、每个学科可以拥有多次独立会话。用户可继续最近会话或新建会话。完整历史可查看，但新会话只注入相关历史摘要和当前学习画像，不无限携带全部消息。

会话实体包括：

- `TutorConversation`：孩子、学科、学段、智能体版本、状态和最近活动时间。
- `TutorMessage`：角色、内容、生成状态、模型调用和时间。
- `MessageAttachment`：与 `FileObject` 关联的图片输入。
- `TutoringSummary`：会话结束后的结构化学习记录及其证据状态。

### 9.4 对话链路

`选择学科 -> 新建或继续会话 -> 输入文字或上传图片 -> 检查额度 -> 调用模型 -> 分块流式展示 -> 保存消息和用量`

- 图片先上传 COS，消息保存受控文件引用。
- 用户可以停止生成。
- 中断时保留已生成内容并标记未完成。
- 流式通道异常时可降级为一次性响应。
- 主模型失败且尚未产生有效回复时，可以切换备用模型。
- 两个模型都失败时展示可重试错误，不保存伪造回复。

会话结束或长时间闲置后，Worker 生成 `TutoringSummary`，提取知识点、困难、表现和建议，并将摘要写入学习证据。

### 9.5 额度与用量

- `TutorQuotaAccount` 保存家庭共享的“智学”可用额度；多个孩子共同使用该额度池。
- `TutorQuotaLedger` 保存赠送、预占、结算、释放和人工调整流水，并为每笔实际使用记录 `childId`。
- 家庭额度使用平台内部统一“辅导积分”，不直接暴露不同供应商不可比较的原始 Token。每个模型配置包含 Token、图片和请求的积分换算规则。
- 调用前按最大可能消耗预占积分，完成后按实际 Token、图片用量和模型换算规则结算。
- 失败或取消释放未使用额度。
- 并发请求使用唯一流水和事务防止重复扣费。
- `TutorQuotaLedger` 通过调用 ID 关联 `ModelUsageLedger`，但平台模型成本和用户额度保持两个独立账本。
- 本次没有在线购买入口。

### 9.6 明确排除

V2 不实现录音、音频上传、语音转写、语音播放、实时音频流或全双工语音接口。

## 10. 真人家教系统

### 10.1 老师申请与审核

老师从“我的”发起身份申请，提交身份、学历、教师资格、科目、学段、经历、价格和可授课时间。资质文件保存到私有 COS。

申请与审核实体包括 `TeacherApplication`、`TeacherQualification` 和 `TeacherAuditRecord`。公开的 `TeacherProfile` 只引用审核通过且允许展示的字段。

状态为：

`草稿 -> 已提交 -> 审核中 -> 补充材料 -> 已通过 -> 已暂停 / 已封禁`

超级管理员记录每项材料的审核结果、审核时间和原因。前台只展示平台核验结论，不暴露证件原件。

### 10.2 老师工作台

老师使用同一微信账号进入角色专属导航：

`工作 | 课程 | 学生 | 我的`

- `工作`：待处理试听、待反馈课程和审核通知。
- `课程`：可授课时间、试听排期、改期和课程状态。
- `学生`：已建立服务关系的孩子及授权学习摘要。
- `我的`：老师申请、资质进度、公开资料和账号设置。

普通家长首次进入不显示角色选择弹窗。只有已审核老师可以切换到老师工作区。

纯老师申请者通过次级“老师入驻”入口进入申请流程，无需创建 `ParentProfile` 或 `Child`。审核通过后直接进入老师工作区；如果以后创建家庭档案，才获得家长工作区。

### 10.3 可解释推荐

首期使用确定性规则评分，不训练推荐模型：

1. 科目、学段、审核状态和可用时间为硬条件。
2. 授课方式、预算、经验和距离等作为筛选条件。
3. 老师教学标签与孩子学习偏好、薄弱点形成兼容评分。
4. 推荐卡展示具体原因，不直接暴露 MBTI 标签或敏感画像结论。
5. 家长可以跳过推荐，自主浏览所有符合硬条件的老师。

### 10.4 试听与课程

核心实体包括：

- `TeacherAvailabilityRule` 与 `TeacherAvailabilityException`：周期可用时间和特定日期例外。
- `TrialBooking` 与 `BookingChange`：试听申请、改期和状态历史。
- `Lesson`：已确认的课程时间和完成状态。
- `TeacherFeedback`：老师署名的结构化课后反馈。
- `ParentReview`：与家长、老师和已完成课程绑定的真实评价。
- `DataGrant`：家长授予老师的数据范围、起止时间和撤销状态。

试听状态为：

`已申请 -> 老师接受 / 建议改期 / 拒绝 -> 家长确认 -> 待上课 -> 已完成 / 已取消`

确认试听后创建限于必要范围的 `DataGrant`。老师只能读取孩子称呼、年级、目标、相关薄弱摘要和教学偏好。家长可随时撤销授权。

课程完成后老师提交结构化反馈，包括本节内容、表现、困难和建议。反馈进入学习证据。家长随后可以提交与该课程和家长身份绑定的真实评价。

可授课时间、例外时段和已确认课程共同参与冲突检查。接受或改期使用数据库事务与版本检查，避免重复占用同一时段。

### 10.5 明确排除

V2 不实现课程包、在线支付、退款、平台分账、会员、老师收入或提现。现有演示入口必须移除、隐藏或明确停用。

## 11. 家长端信息架构

### 11.1 首次流程

`微信登录 -> 家长称呼 -> 创建孩子 -> 年级与学习目标 -> 学情引导`

错题诊断和学习风格测评均可跳过。完成或跳过后，日常默认进入“智学”。

### 11.2 一级导航

- `智学`：学科智能体、最近会话和辅导摘要。
- `家教`：画像推荐、老师浏览、详情和试听状态。
- `学情`：执行两项评估、查看最近一次即时结果和重新评估。
- `我的`：孩子管理、综合报告、历史记录、待办、通知、预约、额度和设置。

详细综合画像、历史趋势和 PDF 集中在“我的”，不堆叠在“学情”执行页。

## 12. 站内通知

本次不调用微信订阅消息，只实现小程序内通知中心。

通知类型包括：

- 学情报告生成成功或失败。
- AI 额度不足、智能体不可用等系统事件。
- 试听申请、接受、拒绝、改期和课程状态变化。
- 教师审核结果和补充材料请求。

通知支持未读数量、已读状态、类型筛选和业务实体跳转。用户只有打开小程序后才能看到通知，本次不承诺微信外部提醒。

## 13. 文件与云资源

### 13.1 腾讯云 COS

COS 保存：

- 错题和作业图片。
- 教师资质材料。
- 报告 PDF。
- 后续业务需要的受控附件。

数据库通过 `FileObject` 保存对象键、类型、大小、所有者、所属孩子、业务用途和状态。Bucket 默认私有，客户端通过后端获取短期签名上传或下载地址。COS 密钥只存在服务端环境变量中。

微信公众平台必须登记 API 请求域名、COS 上传/下载域名和报告访问域名。Worker 调用模型时根据对象键即时生成服务端签名地址，不把过期签名 URL 持久化到数据库。

### 13.2 PostgreSQL 与 Redis

- 生产 PostgreSQL 使用用户已有的腾讯云数据库。
- 使用独立生产账号、SSL、网络白名单和自动备份。
- 测试库与生产库严格隔离。
- Redis 用于 BullMQ 或等效任务队列，不作为业务事实的唯一存储。

### 13.3 Beta 容量基线

- 20 至 200 个家庭账号。
- 每个家庭最多 5 个孩子。
- 约 50 位认证老师。
- AI 调用受额度、并发和模型超时限制。
- 单台应用服务器运行 Admin 和 Worker，云数据库、Redis、COS 为外部依赖。

本次不引入 Kubernetes、微服务或复杂分布式基础设施。

## 14. 运营后台

后台导航按业务域组织：

- `运营概览`：家庭、孩子、评估、AI 成本、试听转化和待办。
- `家庭管理`：家长、孩子、账号状态、画像、报告和额度调整。
- `学情中心`：评估任务、失败重试、报告、PDF 和分享状态。
- `智能体中心`：学科智能体、提示词版本、模型配置、发布测试、调用日志和成本。
- `教师管理`：申请、资质审核、公开资料和服务状态。
- `教务管理`：试听、排期、课程、反馈和评价。
- `通知中心`：站内通知记录和失败状态。
- `系统设置`：平台参数、依赖连通状态、审计日志和管理员密码。

本次仅支持超级管理员。模型密钥只能覆盖更新，不能读取明文。提示词发布、模型变更、额度调整、教师审核、报告删除等敏感操作必须写入 `AuditLog`。

## 15. 异常处理与幂等

API 使用统一错误码和响应结构，至少区分：

- 输入错误。
- 未登录。
- 权限不足。
- 额度不足。
- 资源冲突。
- 模型不可用。
- 任务失败。
- 系统异常。

小程序根据错误码决定恢复动作，不解析后端中文文案控制业务逻辑。

以下操作必须幂等：

- 微信登录重复回调。
- 评估任务创建。
- PDF 生成。
- 老师反馈提交。
- 试听确认与改期。
- AI 额度预占和结算。

异步任务使用有限重试和死信状态。临时网络、模型限流和超时可以自动重试；Schema 不合法和文件损坏等确定性错误直接失败。管理员可以人工重试，但不能人工伪造成功结果。

小程序断网、切后台或流式中断时保留消息和任务 ID；恢复后查询服务器状态。未知状态不得自动重复调用模型或扣费。

## 16. 隐私与安全

- 所有孩子数据通过家长身份和 `childId` 所属关系校验。
- 老师访问同时要求服务关系和有效 `DataGrant`。
- 权限检查在领域服务执行，不能只依赖前端路由或中间件。
- COS Bucket 私有，所有访问使用短期签名。
- 模型密钥加密保存，日志与错误信息脱敏。
- 上传文件校验类型、大小、数量和所有权。
- 家长可以删除原始评估图片、完整 AI 会话和报告。删除证据来源时必须撤销关联 `LearningEvidence`，重新计算当前画像，并撤销或重建依赖该证据的当前报告。
- 老师提交的课后反馈是老师署名的服务记录，家长不能直接篡改或单独删除；家长可以申请更正、撤销老师后续访问，或在删除整个孩子档案时按统一流程清理。
- 删除孩子档案先进入 30 天可恢复期，之后清理关联文件并匿名化必要审计记录。
- 分享链接使用高熵随机令牌，对数据库只保存令牌哈希，并记录有效期和撤销状态。
- 孩子没有独立登录，数据控制权归家长账号。
- 删除和撤销操作必须写入审计记录，但审计记录不得保留已删除敏感正文。

## 17. 部署与可观测性

### 17.1 发布流程

1. 安装冻结锁文件依赖。
2. 运行格式、类型、单元和集成检查。
3. 验证 Prisma migration 可在全新数据库执行。
4. 构建 Admin 和 Worker 镜像。
5. 在发布步骤中显式执行 migration。
6. 启动新容器并通过就绪检查。
7. 健康后切换流量，旧容器暂时保留用于回滚。

应用启动命令不得自动执行未经审核的数据库迁移。迁移失败必须阻止新版本切换流量。

Nginx 对 AI 流式接口关闭代理缓冲和响应压缩，并配置独立的读取超时；其他普通 API 继续使用常规缓冲。小程序流式协议使用 UTF-8 NDJSON 事件帧，每行包含 `type`、`sequence` 和 `data`。客户端按字节增量解码并缓冲到换行符后再解析，不得假设任意网络分块恰好对应一条完整消息。

### 17.2 监控

至少监控：

- API 错误率与延迟。
- AI 流式调用中断率。
- 模型耗时、Token 和费用。
- 队列积压、重试和死信任务。
- Worker 存活与消费延迟。
- PostgreSQL、Redis 和 COS 连接错误。
- 微信登录失败率。

日志采用结构化格式，包含请求、用户、孩子、会话或任务关联 ID。日志不得记录模型密钥、完整系统提示词、证件原件或未脱敏敏感正文。

## 18. 测试策略

### 18.1 基线

- 统一并提交 `pnpm-lock.yaml`。
- CI 使用冻结锁文件安装。
- 每个里程碑必须通过类型检查、测试、后台构建和微信小程序构建。

### 18.2 测试层次

- 纯函数测试：学习风格计分、可信度、推荐评分、额度结算。
- 领域服务测试：微信身份、多孩子权限、评估状态机、会话、预约冲突、授权和反馈。
- API 契约测试：请求 Schema、错误码、幂等、流式分帧、中断恢复和越权访问。
- 集成测试：真实测试 PostgreSQL 与 Redis；模型、COS 和微信接口使用可控替身。
- Worker 测试：成功、重试、超时、死信、重复消费和费用释放。
- 任务一致性测试：Redis 重启或任务过期后，数据库 `AsyncJob` 仍能准确反映并恢复任务状态。
- 小程序流程测试：家长登录建档、纯老师入驻、两项评估、报告、AI 会话、切换孩子、试听和反馈。
- 数据一致性测试：删除评估或会话后撤销证据、重算画像并更新当前报告。
- 账本测试：家庭共享额度的并发预占、按孩子归因、失败释放，以及与全局模型成本账本的关联。
- 真机验收：微信授权、图片上传、分块响应、切后台恢复、弱网和不同屏幕尺寸。
- 安全测试：跨家庭访问、老师越权、失效分享、文件签名和后台敏感操作。

### 18.3 里程碑验收

V2.1 验收：

- 新用户通过微信登录并管理多个孩子。
- 两项评估可以独立完成和失败重试。
- 画像、报告和 PDF 可追溯且无虚假降级数据。

V2.2 验收：

- 管理员可测试、发布和回滚学科智能体。
- 孩子可进行文字与图片流式辅导。
- 会话历史、摘要、画像回流、额度和成本日志正确。

V2.3 验收：

- 老师可申请、补充材料并审核上线。
- 家长可以获得可解释推荐并完成试听和排期。
- 课程反馈与真实评价能够回流孩子画像。

## 19. 非目标

以下内容不属于 V2：

- 原生 iOS 或 Android App。
- 正式 H5 客户端。
- 任何语音或全双工能力。
- 第三种评估模块或通用题库编辑器。
- 错题本和复习计划。
- 孩子独立账号。
- 微信订阅消息。
- 在线支付、课程包、退款、分账、会员、收入和提现。
- 自定义 RBAC。
- 机器学习推荐模型。
- 微服务、Kubernetes 和大规模高可用架构。
- 无损迁移现有演示数据库。

## 20. 实施约束

- 保留当前工作区中用户已有的发布加固与视觉改动，不回退无关修改。
- 先建立测试与依赖基线，再进行业务重构。
- 每个模块通过稳定契约与其他模块交互，API 路由不得成为业务逻辑容器。
- JSON 只用于版本化快照或供应商原始响应；需要查询、约束和统计的核心字段使用明确关系与类型。
- 不允许使用随机数据、静态老师或虚假统计作为生产失败兜底。
- 每个里程碑使用独立实施计划，按小步迁移保持主干可运行。
